## Implemented behavior and contract limits

- Verified email, active selected church membership, actor/role/assignment binding and current Owner MFA precede protected report/ministry reads. Teacher sessions and ministry choices must match current assignments; unexpected Owner/export payloads fail closed. Existing server authorization and forced RLS remain authoritative.
- Accessible From/To/Ministry filters separate draft choices from applied results. Reports and server CSV use the same applied allowlist: date_from, date_to and optional ministry_id. Recoverable field failures preserve safe inputs and hide old results; only allowlisted field names appear in feedback.
- Defaults remain UTC today minus 30 days through UTC today. Recorded calendar-date boundaries are inclusive and are not converted to device timezone. The server permits dates up to 366 days apart, including the same date; impossible/reversed/out-of-bound dates are rejected. Browser proof deliberately uses America/Los_Angeles at a UTC midnight boundary.
- Present, Absent, finalized-record count and rate come from the authoritative summary, not the recent-session list. The existing history response contains at most 100 recent finalized/revised sessions, while aggregate totals and server export cover all eligible rows. A real-backend 101-session fixture proves that distinction.
- Pending server sessions, matching local device events, conflicts and append-only revision counts remain distinct. Local counts are read only after encrypted actor/church/lease verification and a post-read current-authorization check. Locked, unrelated or unavailable device work is unknown, not zero or completed synchronization. Local events cover the matching profile's dates, not the report range.
- Semantic summaries, a captioned table with column headers and a keyboard scroll region, wrapping mobile cards and read-only disclosures expose supported session fields. Correction links open those loaded disclosures and restore summary focus on reload. No individual revision-entry/student-detail read endpoint or editor is implied or called; immutable originals and append-only revisions stay unchanged.
- Loading, empty, unavailable/error, unauthorized/expired and offline states are distinct. A selected ministry absent from current choices keeps an explicit generic selected option while authorized; no name is invented, and revocation removes it. Scope/session/offline invalidation clears protected results/options and suppresses late report, local-count and CSV completions. Generation-valued operation guards permit deliberate fresh reads without old completions releasing new operations.
- Owner CSV is deliberate and coalesces repeated in-flight clicks. Current identity/assurance is rechecked; the actual server Blob is downloaded unchanged and temporary URLs are released. Feedback states that the download was handed to the browser, not that it completed. Failures never generate a client substitute. Existing audited UTF-8/BOM/CRLF export and formula-prefix escaping remain server-enforced.
- Shared navy/blue/emerald styling reflows filters, summaries and history without page overflow. Keyboard visibility follows the existing pointer-safe Attendance/Import pattern: a focused control concealed by phone navigation is revealed after native focus processing, while pointer targets are not moved between press and release.

Production backend and generated contracts, schemas, permissions, dependencies and governance are unchanged. The shared church transport and existing cryptographic formats remain intact, as do offline storage writers, attendance and synchronization. Security and CI configuration is unchanged.
