## Implemented contract

`X-MSprout-Attendance-Reader` is optional on protected attendance operations. Missing means `three-state-v1`, which is the only accepted B3 profile. Empty, malformed, list-valued and observable duplicate values return HTTP400 `invalid_attendance_reader`; syntactically valid unsupported values, including reserved `late-v1`, return HTTP400 `unsupported_attendance_reader`. It is compatibility information, never authorization or binary attestation.

Authorized incompatible requests return HTTP409 `attendance_compatibility_required`. The existing full-bootstrap refusal is separately classified HTTP409 `full_bootstrap_required`, without implementing recovery. All four errors use fixed privacy-safe text, request correlation identity and `Cache-Control: no-store, private`. Compatibility responses contain no results, lease, cursor, partial domain data or `required_reader`. Bodies, successful schemas, event IDs/hashes, terminal result states, routes and three-state enums remain unchanged. [OpenAPI](../../contracts/openapi.yaml) and [generated types](../../apps/web/src/api/generated.ts) change together.

The current client declares `three-state-v1` only on affected requests and allowlists typed errors into fixed accessible preservation messages. Legacy and B2 assets are unchanged and send no declaration. No compatibility response invalidates authorization, logs out, deletes storage, settles events, forces a reload, invokes bootstrap or activates a worker. Existing 401/403 behavior and bounded retries remain intact. Existing explicit recovery still refreshes bootstrap before Sync; B3 does not repair that B4 concern.

## Receipt, transaction and cursor invariants

Existing receipt lookup/actor/hash checks remain authoritative. Replay-only batches return accepted-duplicate, conflict or rejected evidence without reevaluating their current session as fresh intent. Fresh supported operations retain normal results, including stale-version conflict handling and dependent draft-then-mark batches. Mixed replay/fresh/incompatible requests refuse without new terminal receipts or domain/audit/feed effects; earlier receipts and earlier successful chunks/pages remain accepted. Natural-key draft collisions are checked before creating a new conflict receipt.

Whole-batch blocking is deliberate and stakeholder-approved: safe events in that chunk and later chunks can remain queued. No splitting, reordering, deletion, regenerated IDs or implicit rebasing is introduced.

Laravel can render a downstream exception into an HTTP response before tenant middleware's transaction callback returns. Therefore an HTTP409 alone does not establish rollback. Dedicated domain closures surround upload processing and pull cursor/lease effects. Test-only fault listeners throw after an actual cursor insert or receipt insertion; loopback HTTP cases exercise normal login/cookies/CSRF and require all checked domain tables to remain unchanged after rendering.

Authorization-filtered gaps and targeted assignment tombstones remain valid. Another successful concurrent request may legitimately advance shared state; refusal guarantees zero effects attributable to that request, not reversal of another transaction. The server cursor still records served/scanned progress, **not durable client acknowledgment**.
