## Confirmed causes and correction

The shared boundary's hidden visibility event replaced ready state with loading. Both visible and focus events restarted sequential `/auth/session` then scoped `/api/me` discovery/preflight; overlapping requests could run even though generation guards rejected stale completions. The child key included the refresh revision, so every successful refresh remounted the active module and repeated its initialization requests. No persistent workspace cache was involved.

Activation now retains only the already-validated view while that same server discovery/preflight runs in the background. An in-flight guard coalesces visible/focus checks; hidden focus does not trigger a request. Unchanged actor, church, role and canonical ministry-assignment scope preserve the module instance and its local state. An authorization-scope change remounts the module and discards its previous projection. This is authorization reuse within the mounted route, without a TTL, persistent cache, skipped activation preflight or relaxed API authorization. Existing initial child `/api/me` calls are retained; unnecessary refresh remounts and their repeated data calls are removed.

Import previously initialized `owner=false`, rendering the forbidden explanation before the asynchronous account/ministry initialization completed. It now distinguishes loading, authorized, forbidden and error, binds the result to the requested church, and shows its controls/preview only for a positively resolved active Owner with confirmed current-session MFA. Initialization failures show the existing sanitized error rather than a false denial.
