# Shared UI foundations

Use these presentation components with existing domain controllers and server authorization. They do not authorize actions or read/write stored data.

- `Button` defaults to `type="button"`; choose `type="submit"` explicitly. `primary` uses the approved blue gradient, `secondary` is outlined, `quiet` is a lower-emphasis text action, and `danger` is reserved for destructive actions. Preserve one dominant action per context. `busy` disables the action and exposes `aria-busy` without adding a second spinner or changing its accessible name; the controller supplies truthful contextual feedback. Disabled hover retains its treatment. Keep safety-critical text and existing duplicate-submit protections.
- `Field` creates a unique input/label relationship, combines caller descriptions with hint/error IDs, and exposes invalid state. Keep safe inputs on failure and clear secrets under the existing controller's rules. Native selects/textareas use the same global control styling and require explicit labels and linked error descriptions.
- `ErrorSummary` announces safe text and focuses linked fields. The form controller focuses its summary after a failed deliberate submission. Never pass raw server responses or protected data into public errors.
- `StatusBadge` and `StatusBanner` default to neutral. `live` is opt-in for a banner; use it only for meaningful changes. `LoadingState` is an atomic polite status with visible contextual text and one decorative, static indeterminate mark. It exposes no percentage, range, timer or estimated completion. Do not leave loading mounted when work is paused, offline, failed or awaiting input; the existing feature controller owns that state. Success requires confirmed evidence. Absent and offline are neutral; needs-review is warning; failure is danger. Persistent errors/recovery belong in the existing summary/banner; no toast subsystem or new success claim is introduced.
- `StepIndicator` renders a named ordered list with `aria-current="step"`, visible stage labels and text identifying the current stage. Features supply stable IDs and their actual current stage; missing IDs produce no guessed selection. There is no inferred completion, percentage, navigation or state controller. Preparation and Import reuse it with their existing CSS class adapters and unchanged workflow state. Their headings continue to announce stage changes through existing focus behavior. Completion/error decoration requires explicitly verified feature state in a separately selected retrofit.
- `Dialog` is controlled with `open` and `onClose`. Keep its trigger mounted and supply `returnFocus` pointing to that trigger, including for pointer/touch activation on Safari. Supply `initialFocus` for the safe action; otherwise the title receives focus. Native modal isolation and explicit Tab/Shift+Tab wrapping contain focus. Escape requests close; confirmation belongs to the domain controller. The dialog never submits an action by itself.
- `Tabs` uses automatic keyboard activation with Left/Right, Home/End and one tab stop. Supply stable, unique item IDs. Inactive panels stay mounted and hidden; clear protected plaintext at the domain boundary when authorization expires or a profile locks.
- `ResponsiveTable` provides a named keyboard-accessible overflow region and table caption. Supply semantic headers and cells; never replace row semantics with clickable containers. `ResponsiveList` supplies responsive list spacing; callers supply list items and accessible actions. Choose the supported screen's table/card presentation without duplicating interactive controls.

Shared CSS retains visible focus, enlarged text, reduced motion and forced colors. Screens still require their own keyboard, narrow-viewport, state, privacy and domain checks. The isolated examples in `e2e/fixtures/ui-foundations.tsx` are bundled in memory for tests and are excluded from the application build; no demo route is shipped.

## Ownership and migration boundaries

`styles/tokens.css` owns semantic color/gradient, typography, spacing, radius, focus, motion and responsive-dimension values. `styles/global.css` owns the native reset, typography, focus and form controls. `styles/foundations.css` owns `.ui-*` primitives, shared action variants and feedback. The old duplicate global base in `index.css` and native-control/focus definitions in `App.css` are consolidated into that owner. Existing native control geometry is preserved; shared buttons use 14px text, 12px radius and at least 44px targets. Inputs stay 16px by inheritance on ordinary phone forms to avoid zooming merely to type.

The semantic title scale is 24/20/18px. The legacy 32/24/20px heading aliases deliberately preserve unmigrated compositions; UX-F2/F3 and selected pack tasks own their migration and browser approval. Brand and workflow font/geometry exceptions remain scoped adapters, not a second global reset. The 1152px content, 640px focused-form and 24/20/16px gutter tokens establish subsequent composition values without silently resizing existing screens. Native media queries retain 768/1024px boundaries because custom properties cannot define native query conditions.

| Retained adapter | Removal owner and prerequisite |
|---|---|
| `App.css` role feedback, form widths, application actions and old feature layouts | Selected UX-F2/F3/pack task, then UX-15 consistency closure; migrate actual consumers and prove loading/error/form/recovery states first. |
| `index.css` roster and older import rules | People and Import retrofit tasks; identify remaining consumers before removal. |
| Branding, shared navigation, Home and device-profile styles | UX-F2; preserve approved branding, light navigation, blue gradients and current geometry until its separate acceptance. |
| Preparation, Sync and attendance styles and local token overrides | UX-F3; preserve accepted layouts, absence/success semantics and all encrypted-work guarantees. Stepper extraction in UX-F1 changes presentation ownership only. |
| People, Import, review, report, birthday/activity and platform styles | Their separately selected pack tasks; retain supported actions, authorization and screen-specific control/overflow exceptions. |

Use existing semantic headers and `.application-actions` / `.ui-dialog-actions` before adding layout components. Keep Cancel before confirmation and Back before Continue; preserve existing contextual wrapping and action order. Existing `HomeIcon` remains the icon owner; shared button icons use its 20px dimensions, are decorative when visible text names the action, and need contextual accessible names plus 44px targets when alone. No new icon/framework dependency is introduced.

No existing consumer exposes a reliable overall completion total. UX-F1 therefore adds no unused determinate-bar API. A future selected feature with measured work must supply reliable current/total values, a visible stage description and native `progress` (or correct named ARIA range semantics); unknown totals stay indeterminate with no `aria-valuenow`. Sync retains independent upload/download and durable-application wording; its presentation retrofit belongs to UX-F3. Import remains governed by actual batch stages and partial outcomes. Never manufacture telemetry, endpoints, progress estimates or completion to populate an indicator.
