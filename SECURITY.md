# Security policy

## Reporting a vulnerability

Use the repository's private GitHub Security Advisory reporting flow. Do not open a public issue or include production credentials, cookies, access tokens, private child data, raw request bodies, or exploit traffic from systems you do not own. Include the affected commit, route or component, impact, minimal reproduction with synthetic data, and any correlation ID that is safe to share.

Do not perform denial-of-service testing, social engineering, persistence, destructive data changes, tenant-boundary probing against real churches, or access beyond the minimum needed to demonstrate the issue. Stop immediately if real child or guardian data becomes visible.

Maintainers should acknowledge the report through the private advisory, preserve relevant audit/security evidence, classify tenant/privacy impact, rotate only implicated secrets, and coordinate remediation and disclosure there. No release is eligible with an unresolved high or critical finding.

## Supported version

Until the first production release, only the latest commit on the active MVP feature branch is supported. After release, this file must be updated with the supported production line and security-update policy.
